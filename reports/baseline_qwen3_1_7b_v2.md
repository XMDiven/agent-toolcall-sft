## 0. 为什么作废 v1

独立复核发现 v1 存在四个问题，逐条复现后全部属实：

| 问题 | v1 的实际情况 |
| --- | --- |
| 跨 split 模板泄漏 | 30 个句式、90 条记录跨界，manifest 却报告 `leakage_clean: true` |
| manifest 未冻结标签 | 只哈希 id + template_key + messages，改 `expected_decision` 后 hash 不变 |
| 提示词非模型原生格式 | 使用自定义 JSON 信封，未向 chat template 传 `tools=` |
| "整体行为准确率"命名不准 | 实为四分类准确率；工具或参数错误仍计正确 |

**其中提示词问题影响最大**，见第 4 节的消融实验。

### 两个准确率的区别

`action accuracy` 只比对四种决策类型；调错工具或传错参数仍计正确。
`end-to-end accuracy` 要求 Schema 合法、决策类型正确，且工具调用的**工具名与参数全部正确**。

v1 报告把前者称作"整体行为准确率"，**高估了模型的可用程度**。本报告两者并列，主结论以 end-to-end 为准。

## 4. 消融实验：提示词协议的影响

v1 → v2 同时更换了数据与提示词，**整体差值无法归因给任一方**。为此固定数据为 v2，仅把提示词换回 v1 的自定义信封，在同一批 200 条上重跑：

| 指标 | v1 自定义信封 | v2 原生协议 | 差值 |
| --- | ---: | ---: | ---: |
| 工具 Schema 合法率 | 86.0% | 92.0% | **+6.0 pp** |
| action accuracy | 40.0% | 48.0% | **+8.0 pp** |
| end-to-end accuracy | 37.0% | 41.0% | +4.0 pp |
| **工具名准确率** | 25.0% | 39.8% | **+14.8 pp** |
| 参数 exact match | 20.4% | 29.5% | **+9.1 pp** |
| **危险写工具误调用率** | **8.5%** | **1.6%** | **−6.9 pp** |

产物：`artifacts/ablation_v1prompt_v2data.json`，sha256 `c6a1861af21ef6d975ff2194619d9a035b643f97056b8658bfe9ea823da299ce`

### 结论

**v1 基线的低分主要由提示词协议造成，而非模型能力。**

最重要的一条：v1 报告称基线的危险写工具误调用率为 7.5%，据此暗示"基线不安全"。消融显示，在同一批数据上仅换协议即可降到 1.6%。**那个结论是提示词造成的假象。**

若当时以 v1 为基线开始微调，"提升"中将包含约 15 个百分点的纯格式学习——**微调会被记入本不属于它的功劳**。

## 5. 主要失败模式

### 5.1 Schema 失败全部是同一种格式冲突（41 次）

```json
{"action": "get_order_status", "tool_call": {"name": "get_order_status", ...}}
          ↑ 应为 "tool_call"，或直接使用 <tool_call> 标签
```

41 次失败**无一例外**都是把工具名填进 `action` 字段。在原生协议下这尤其说明问题：模型手上有 `<tool_call>` 标签可用，却在标签之外另写了一个自定义信封——**它在两种格式之间摇摆**。

这是真实的模型缺陷，也是微调最直接的目标。

> **不再声称这些调用"嵌套部分完全正确"。** v1 报告第 100 行有此说法，实测不成立：v1 的 64 条中，仅修正外层字段后只有 52 条通过 Schema、50 条工具名正确、**27 条参数完全正确**。该结论当时基于抽看数例得出，未经测量。

### 5.2 转人工严重不足

该 `handoff` 的 99 条中判对 27 条（27.3%）。模型把强烈投诉、法律纠纷、越权请求大量处理成 `clarify` 或 `direct_answer`——**继续对话而非升级**，这在真实客服中是有风险的行为。

### 5.3 knowledge 域端到端仅 9.0%

Schema 合法率 79.0% 是四类中最低，说明知识工具的调用格式对基线最难。相比 v1 的 0.0%，已不再是退化子集。

## 6. 读这些数字时必须知道的五件事

### 6.1 提示词自此冻结

`PROMPT_VERSION = v2` 不再改动。微调模型必须使用同一提示词，否则本报告作废。

### 6.2 有效样本量小于 500

测试集 500 条来自 **190 个不同 `template_key`**，平均每个内容复用 2.6 次。bootstrap 的独立性假设因此并不严格成立，**真实置信区间比按 n=500 计算的更宽**。

v2 相对 v1（90 个内容）已改善 1.45 倍，但仍未达到 1 条 1 内容。阶段 C 报告置信区间时必须同时给出 `template_key` 计数。

### 6.3 危险误调用率已接近门槛

ROADMAP 的门槛是 ≤2%，基线已是 2.1%（另一口径 2.0%）。**微调在这一维度上的提升空间很小**，项目结论不应以此为主要卖点。空间较大的是工具名准确率（40.8%）与 end-to-end（38.4%）。

### 6.4 knowledge 子集 n=100

95% CI 半宽约 ±10 个百分点，只能检出较大效应。

### 6.5 数据标签本身可能有误

见 `reports/data_audit_v2.md` 第 4 节。阶段 C 的错误分析必须把"标签可能有误"列为候选归因。
